# 🔐 Advanced Telegram Encryption Bot

Профессиональный бот-шифровальщик для Telegram с максимальной безопасностью и современными криптографическими возможностями.

## 🛡️ Возможности безопасности

### Шифрование
- **AES-256-GCM** - Authenticated Encryption (основной алгоритм)
- **ChaCha20-Poly1305** - Быстрое шифрование для мобильных устройств
- **RSA-4096** - Асимметричное шифрование для обмена ключами
- Аутентифицированное шифрование (защита от подделки)

### Обмен ключами
- **X25519 (Curve25519)** - Эллиптическая криптография для ECDH
- **Perfect Forward Secrecy** - Эфемерные ключи для каждой сессии
- **HKDF** - Безопасная деривация ключей
- Автоматическая ротация ключей через 24 часа

### Цифровые подписи
- **Ed25519** - Быстрые и безопасные подписи
- Временные метки для защиты от replay-атак
- Проверка подлинности сообщений

### Стеганография
- LSB (Least Significant Bit) встраивание в изображения
- Скрытие зашифрованных данных в PNG/BMP
- Автоматический расчет вместимости

### Защита
- **Rate Limiting** - Защита от флуда и DoS
- **Input Validation** - Проверка всех входных данных
- **Anomaly Detection** - Обнаружение подозрительной активности
- **Secure Memory** - Безопасное удаление ключей из памяти
- Временная блокировка при подозрительной активности

## 📋 Требования

- Python 3.11+
- Docker и Docker Compose (опционально)
- Telegram Bot Token от @BotFather

## 🚀 Установка

### Вариант 1: Docker (Рекомендуется)

1. Клонируйте репозиторий:
```bash
git clone <repository-url>
cd telegram-encryption-bot
```

2. Создайте `.env` файл:
```bash
cp .env.example .env
```

3. Добавьте токен бота в `.env`:
```env
TELEGRAM_BOT_TOKEN=your_bot_token_here
```

4. Запустите с Docker Compose:
```bash
docker-compose up -d
```

### Вариант 2: Локальная установка

1. Установите зависимости:
```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate  # Windows

pip install -r requirements.txt
```

2. Создайте `.env` файл и добавьте токен

3. Запустите бота:
```bash
python main.py
```

## 📚 Использование

### Основные команды

#### 1. Простое шифрование
```
/encrypt Секретное сообщение
```
Зашифрует ваше сообщение с помощью AES-256-GCM

#### 2. Расшифровка
```
/decrypt <зашифрованные_данные>
```
Расшифрует сообщение

#### 3. Генерация ключей
```
/genkeys
```
Создаст:
- RSA-4096 ключи (асимметричное шифрование)
- Ed25519 ключи (цифровые подписи)
- X25519 ключи (обмен ключами)

#### 4. Создание защищенной сессии (E2EE)
```
/session <публичный_ключ_партнера>
```
Создает end-to-end зашифрованную сессию с Perfect Forward Secrecy

#### 5. Цифровая подпись
```
/sign Важное сообщение
```
Создает цифровую подпись с временной меткой

#### 6. Стеганография
```
/stego
```
Затем отправьте текст и изображение - данные будут скрыты в изображении

#### 7. Извлечение из стеганографии
```
/extract
```
Отправьте изображение со скрытыми данными

#### 8. Статус безопасности
```
/security
```
Показывает:
- Оставшиеся запросы (rate limiting)
- Статус сессий
- Наличие ключей

## 🔒 Безопасность

### Архитектура безопасности

```
Пользователь → Telegram → Бот (Docker) → Crypto Modules
                                ↓
                          Rate Limiter
                          Validator
                          Security Manager
```

### Что НЕ хранится на сервере:
- ❌ Приватные ключи (только в памяти)
- ❌ Расшифрованные сообщения
- ❌ Пароли

### Что защищено:
- ✅ Автоматическое удаление ключей через 24 часа
- ✅ Защита от брутфорса (rate limiting)
- ✅ Валидация всех входных данных
- ✅ Изолированный Docker контейнер
- ✅ Non-root пользователь в Docker
- ✅ Read-only файловая система

## 🔬 Криптографические алгоритмы

### Симметричное шифрование

**AES-256-GCM** (по умолчанию)
- 256-бит ключ
- Authenticated Encryption
- 96-бит nonce
- Защита от подделки

**ChaCha20-Poly1305**
- 256-бит ключ
- Быстрее на мобильных
- Authenticated Encryption
- RFC 8439 compliant

### Асимметричное шифрование

**RSA-4096-OAEP**
- 4096-бит ключ
- SHA-256 padding
- Для обмена ключами

### Обмен ключами

**X25519 (ECDH)**
- Curve25519
- Perfect Forward Secrecy
- HKDF деривация ключей
- Эфемерные ключи

### Подписи

**Ed25519**
- 256-бит безопасность
- Быстрые подписи
- Малый размер подписи
- Временные метки

### Деривация ключей

**Argon2id**
- Защита от GPU атак
- Memory-hard функция
- 64MB памяти, 3 итерации
- Рекомендовано OWASP

## ⚠️ Важные замечания

### Ограничения

1. **Размер сообщений**: До 4096 символов (ограничение Telegram)
2. **Rate Limiting**:
   - 30 запросов в минуту
   - 500 запросов в час
3. **Время жизни ключей**: 24 часа (автоматическая ротация)
4. **Стеганография**: Только PNG/BMP изображения

### Рекомендации по безопасности

1. **Экспортируйте ключи**: Приватные ключи хранятся только в памяти
2. **Используйте сессии**: Для E2EE общения создавайте сессии
3. **Ротация ключей**: Регулярно обновляйте ключи
4. **Secure environment**: Запускайте в Docker
5. **HTTPS**: Telegram использует HTTPS, но не доверяйте промежуточным серверам

## 🤝 Сценарии использования

### E2EE переписка между двумя пользователями

**Пользователь А:**
```
1. /genkeys
2. Отправить публичный X25519 ключ Пользователю Б
3. /session <публичный_ключ_Б>
```

**Пользователь Б:**
```
1. /genkeys
2. Получить ключ от А
3. /session <публичный_ключ_А>
```

Теперь оба могут шифровать сообщения с общим секретом!

### Скрытое сообщение в изображении

```
1. /stego
2. Отправить текст: "Секретное сообщение"
3. Отправить любое изображение
4. Получить изображение с встроенными данными
5. Отправить кому-то изображение
6. Получатель: /extract → отправить изображение
```

## 🐛 Troubleshooting

### Бот не отвечает
```bash
docker-compose logs encryption-bot
```

### Ошибки шифрования
- Проверьте формат данных (Base64)
- Убедитесь, что используете правильный ключ
- Проверьте срок действия сессии

### Rate limiting
- Подождите 1 минуту
- Проверьте `/security` для статуса
